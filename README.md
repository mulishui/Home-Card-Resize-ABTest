# Home 页切换卡片 AB Test demo

IoT App 首页「设备卡片尺寸」两套方案的可交互原型，用来做 A/B 用户调研。

## 这是什么

页面模拟的是 **编辑态** 下的首页（不是日常使用状态）：用户进来就是在调整卡片布局，所以刻意去掉了房间切换、室内温湿度这些信息，避免干扰测试判断。

| | 方案 A | 方案 B |
|---|---|---|
| 列表卡片排列/尺寸/内边距/圆角/图标/字号 | 完全一致（2026-09-29 第十九轮起，两个方案共用同一套数值） |||
| 切换卡片尺寸的操作 | 点 ⤢ 原地循环切换 | 点 ⤢ 弹出底部面板、横向轮播选择 |

两个方案唯一的差异就是"切换卡片尺寸"这一个交互的操作方式，其余一切（列数、真实列表卡片的视觉规格、拖拽排序逻辑）完全相同——这样用户在 A/B 之间感受到的差异只来自交互方式本身，不会被无关的卡片大小差异干扰。

顶部可以切换：单看方案 A、单看方案 B、两个方案并排对比（并排模式在手机上会自动隐藏，屏幕太窄）。

## 已经能用的交互

- **PC 端空白区域鼠标拖拽滚动设备列表**（2026-09-29）—— 这个 demo 要覆盖手机和 PC 两种打开方式（做 A/B 调研，不知道测试者用什么设备打开），所以桌面端体验跟移动端同样重要。桌面端鼠标没有触摸端那种原生的"按住拖拽内容来滚动"手势，只认滚轮/滚动条，因此在设备列表的空白区域（卡片之间的缝隙、上下留白）补了一个鼠标拖拽换算成滚动的手势；只在真正命中非卡片区域时生效，命中卡片本身完全不受影响（走原有的点选/长按换位逻辑），两者互不干扰
- **方案 B 面板打开时背后列表禁止滚动**（2026-09-29）—— 修复了此前面板出现后、在黑色蒙层区域拖动或滚轮滑动，蒙层下方的设备列表仍会跟着滚动的 bug；桌面端锁 `.screen` 自身的滚动，移动端锁 `document`（两种滚动归属模型见 DESIGN.md），面板关闭后精确恢复
- **长按卡片拖动排序** —— 按住约 0.1 秒进入拖拽，松手落位，其他卡片带动画让位；拖拽浮层拖出手机边框时会被物理裁切掉（不是位置被钳制在框内），跟手体验不受影响
- **点卡片右上角 ⤢**（方案 A）—— 轮播式切换卡片尺寸：按 1×0.5 → 1×1 → 2×1 → 2×2 循环，跳过该设备不支持的档位；所有设备初始都是 1×1，支持哪些档位由 `DEVICES` 里每项的 `sizes` 决定
- **点卡片右上角 ⤢**（方案 B，2026-09-29，第十九轮修正过面板尺寸/居中）—— 从下往上滑出底部面板"Select the card view for your device"，横向轮播预览该设备在每个候选尺寸下的真实样子（图标/设备名/房间/步进器/进度条/门锁信息/扫地机任务网格等都跟真实列表卡片完全一致，只是去掉了勾选圆圈和 ⤢ 尺寸按钮，纯展示不可点击）；轮播是"拖一下只切一张"，类似 banner 切换，不会因为拖得快/远就跳好几张，点圆点可直接跳转；切换判定改成"划动距离超过视口宽度 18%（原 30%，太难触发）或划得够快（快划）"两者任一满足即可（2026-09-29 第二十一轮，见 DESIGN.md 对应章节）；点"Use This Card View"确认后会真的把卡片写入对应尺寸并在方案 B 的网格里重新排布（前面的卡片不受影响，跟方案 A 的"不回填"规则一致）；点 X 或点遮罩取消，不改变卡片尺寸。面板背景跟设备列表背景一致（`#f5f6f8`），卡片本身仍是白色，两者能区分开。**面板预览卡片的宽高走一套独立于真实列表的公式**（d 固定 120px，s=55、m=120、l=250；宽度 M/L 最大 368px 封顶、S/D 是 M/L 宽度折半再减一份间距，封顶封不到时按容器实际宽度走），且不同宽度的预览卡片（S/D 窄、M/L 满宽）都水平居中；轮播视口高度按这个设备**支持的最大尺寸档位固定**（靠 flex 行容器默认的 `align-items:stretch` 机制撑到最高档的自然高度，不用 JS 量测也不用过渡动画），切换到更矮的档位时面板高度原地不动，卡片左右内边距 16px、上下靠 `justify-content:center` 在固定高度里垂直居中（2026-09-29 第二十轮同日修正，取代了此轮更早一版"面板跟着当前卡片自动变高"的错误实现，见 DESIGN.md）；卡片下方新增当前尺寸文案（如"1×0.5"、"2×2"），卡片到文案固定 8px、文案到圆点固定 16px、圆点到确认按钮固定 8px、按钮到面板底边固定 40px，这几个间距在矮档位下不受影响（卡片和文案作为一个整体在固定高度里居中）。面板高度进一步统一按"2×2"这个全局最大档固定（不再是"按当前这个设备支持的最大档"，不同设备最大档不一样会导致点不同品类面板高度跳动），实现靠给不支持 2×2 的设备塞一张不可见、不计入轮播的参照 slide 撑高（2026-09-29 第二十轮同日再追加）。面板细节按用户截图标注逐条对齐（2026-09-29 第二十轮第三次追加）：标题字号 20px；关闭按钮不再跟标题同一行，改成上下堆叠、8px 间距；预览卡片左右到面板边缘 10px；卡片下方尺寸文案 14px；标题下方滑动提示"Swipe left or right to preview other sizes" 15px；滑动提示和尺寸文案颜色都跟卡片房间名文本一致（`#a8abb3`）；圆点到确认按钮 16px；确认按钮改胶囊形（跟批量操作浮层同款）；S 档（1×0.5）预览卡片释放了真实列表里给尺寸按钮/勾选圆圈让位的空间（面板本来就不显示这两个控件），设备名不再容易截断成省略号。移动端窄屏下滚动设备列表不会再意外带出这个面板，面板打开时也会精确贴合手机屏幕底部，不受之前滚动位置影响。方案 B 现在也有一套跟方案 A 同级别的真实排布引擎（`computeLayout`/`relayout` 已参数化成任意列数），拖拽换位判定沿用方案 A 当年的两列判定逻辑（见 DESIGN.md）
- **卡片排布规则**（方案 A）—— 改尺寸不会把已经排好的卡片”回填”挪位：改变某张卡片尺寸时，排在它前面的卡片位置完全不动，只有它自己和排在它后面的卡片会跟着顺势重排，且不会跳回前面已经跳过的空位。1×0.5 卡片比较特殊：单独一张时算法内部仍按占满一个完整 1×1 高度的槽位参与占位判断（不会被别的卡片占用，这片空白也能接住拖拽悬停判定），但如果这半格所在那一行确实没有任何卡片渲染进去，视觉上会把这一行收缩成 0 高度，不留空档；只有列表里紧跟着它、中间没被别的卡片打断的下一张也是 1×0.5，两者才会叠在一起共享同一个槽位。这套逻辑靠 JS 显式计算每张卡片的格子位置（`index.html` 里的 `computeLayout()` / `relayout()`），没有用浏览器原生的 CSS Grid 自动排布
- **拖拽与 1×0.5 配对的关系（不对称）** —— 只保护"落点"、不保护"起点"：拖到一对相邻 1×0.5 中间时，不会拆开插进去，而是被拖卡片和这一整对整体互换位置；但被拖卡片自己如果出发前是配对里的一张，拖走时**只带走它自己**，原地留下的搭档会自然变成孤立的 1×0.5（下方留空半格），不会被一起拖走。同一对里的两张 1×0.5 之间也能直接互相拖拽换上下顺序
- **换位判定的死区** —— 拖进目标卡片中心区域才会触发换位，四周留一圈死区防止边界抖动；孤立 1×0.5 卡片下方预留的空白也算在热区里，不用非得精确拖到那张小卡片本身
- **2×1 / 2×2 拖到任意一行上，整行都是换位热区** —— 棋盘固定两列、m/l 本身总是占满整行宽度，所以横坐标不参与判断：只按拖拽落点的纵坐标定位到目标"行带"（两张 1×1 并排、1×1 + 一对堆叠的 1×0.5、甚至一侧完全没有卡片渲染的真空白，都是同一种情况，统一处理），这一整行涉及到的卡片会被当成一个整体热区，拖到这一行的任意位置（包括卡片中间的缝隙、真空白区域）都能触发换位，触发后保持原有左右顺序整体换出去，行内不设死区；行与行之间同样不设死区——目标行带的命中范围会延伸到跟相邻行带的中点为止，不会贴着卡片自己的渲染矩形留出一条打不到的缝隙
- **2×1 / 2×2 卡片的状态内容**（方案 A/B 通用，2026-09-29 第十八轮起方案 B 也接入同一套内容）—— 支持切到这两档的设备会展示一个状态控件：可调数值型设备（净化器，仅 1×0.5/1×1 两档，无此内容）已收窄不再涉及；客厅空调显示"− 数值 +"步进器（如"− 25°❄ +"）；智能门锁 2×1 显示两行紧凑信息："Last operation: 2025/9/10 17:02"（时钟图标）和"Locked | Door is Closed"（锁图标 + 竖分隔线 + 门图标）；机器人吸尘器 2×2 显示"Taking a break…"状态行（zzz 图标）+ 2×3 任务按钮网格（"Clean Everywhere" / "Whole Home" / 三个"Custom Task"类按钮 + 一条刻意用超长乱码文案演示的截断效果，按钮文字超过 2 行会自动省略号截断，不会撑破卡片）。Smart Hub 显示存储用量条 + 侦测到的事件类型图标（宠物/人脸/动作/车辆），灯类设备显示亮度条（2×2 档再加 White/Color 分段开关 + 色谱选择面板）。存储条 / 亮度条是同一个 `.barlabel` 组件：固定 40px 高、`border-radius` 是高度的一半（胶囊形，不是普通圆角矩形），百分比/用量文案直接摆在条内部、左对齐（不居中）、离胶囊左边缘 16px；Smart Hub 和灯类设备两条胶囊现在完全同款——都是灰阶底色（不再用强调蓝，撤销了此前给 Smart Hub 加的 `#0a84ff`），文案都是常规字重（不加粗）、黑色 70% 透明度，字号统一 13px；Smart Hub 文案前是小存储图标，灯的文案前是小太阳图标，两者风格一致。事件图标 40×40（跟展示条同高），彼此之间头像堆叠式重叠（负间距 + 白色描边），最后一个图标跟卡片右下角的勾选圆圈也是故意重叠、不刻意避让。Front Door Camera 的 2×2 预览换成了用户提供的真实照片（压缩后转 base64 内嵌进 `index.html`，仍是单文件、不引用外部图片资源），`background-size:cover` 等比缩放铺满、多余部分居中裁掉，不会拉伸变形；其余设备的预览占位（色谱面板等）继续用纯 CSS 实现。2×1 只多了横向空间，控件独占卡片下半行、卡片高度不变；2×2 横纵向空间都翻倍，控件放大一档、推到卡片底部（客厅空调、Smart Hub 只支持到 2×1，没有 2×2 档）。目前只做静态视觉展示，不接入真实点击/拖动交互。1×0.5 / 1×1 档位、以及不支持 2×1/2×2 的其余设备完全不受影响；方案 A/B 的卡片高度/内边距/图标/字号自 2026-09-29 第十九轮起已完全一致（不再有"方案 B 更紧凑"的差异化），两个方案现在共用同一套列表卡片视觉规格
- **设备支持的尺寸档位收窄/扩展**（方案 A，2026-09-29）—— 电视、空气净化器、加湿器只支持 1×0.5（S）/ 1×1（D）两档，不再有 2×1/2×2；机器人吸尘器只支持 1×1（D）/ 2×2（L）两档（去掉了 S/M）；智能门锁支持 1×0.5/1×1/2×1（s/d/m）三档。共用的房间名行（`.sub`）新增数据驱动的电池图标：门锁只显示图标（无数字），机器人吸尘器显示"图标 + 100%"，两者互不冲突，其余设备不受影响
- **编辑态卡片多选 + 批量操作**（方案 A/B 通用）—— 直接点击卡片本身（不是长按、不是单独的多选入口）即可选中/取消：选中的卡片**背景保持原来的白色不变**，只靠右下角出现的勾选圆圈指示选中（1×0.5 尺寸空间紧张，勾选圆圈挪到 ⤢ 尺寸按钮左侧、垂直居中显示，避免和按钮打架，大小跟其他尺寸完全一样，只是位置不同）；顶部标题实时显示"N 设备选中"，一张都没选时恢复"编辑卡片"。选中数 ≥1 时，屏幕底部会浮起一条胶囊形工具栏（`border-radius:999px`，2026-09-29 第二十轮从圆角矩形改的），三个按钮（分享 / 收藏 / 更换房间）都是图标在上、文案在下的上下结构，图标 24px、文案 10px 浅灰色（跟房间名文本同一个颜色 `#a8abb3`），上下留白精确 8px（2026-09-29 第二十二轮收紧，原来是 16px）；工具栏本身**自适应宽度、水平居中，不再撑满整行**，按钮之间固定 24px 间隔（2026-09-29 第二十四轮，撤销了此前 `left/right:12px` 撑满 + `space-around` 均分间距的做法）；三个按钮宽度会统一对齐到文案最长的那个（当前是"Move Room"），不再各自按文案宽度参差不齐（2026-09-29 第二十四轮追加，靠 JS 在渲染后实测取最大宽度回写，纯 CSS 做不到"宽度等于兄弟节点最大值"这种效果；文案本身加了 `white-space:nowrap` 防止"Move Room"这种多词文案在测量/渲染时被意外换行，2026-09-30 修正）；点击目前只弹出占位 toast（2 秒后自动隐藏，定位在触发它的这条悬浮菜单正上方，2026-09-29 第二十二轮；移动端下 toast 文案短时仍是正常收缩的窄 pill，只有文案长到自然宽度会超出屏幕左右各 16px 边距时，才封顶到这个宽度并换行，不会无条件撑满，2026-09-29 第二十四轮，同日修正过一版"无条件撑满"的错误实现），不接入真实的分享/收藏状态/换房间逻辑。选中状态是每台手机（每个 `.grid`）各自独立的 DOM 状态，并排对比模式下两侧互不影响。点击判定复用了拖拽逻辑里已有的"长按计时器是否触发过"标志位，长按阈值经过几轮调整目前是 180ms（100ms → 350ms 解决点击误判成拖拽 → 200ms → 180ms，逐步压缩到用户觉得拖拽响应够快、同时点击依然不会误判的区间），保证普通点击稳定判定为选中、只有真正长按才会进入拖拽
- **2×1 / 2×2 卡片的头部对齐 + 间距分布**（方案 A，所有支持这两档的设备统一）—— 图标 + 设备名/房间 + ⤢ 尺寸按钮在同一行（2×2 现在也跟 2×1 一样是头部一行，不再单独堆一行），状态控件独占下一行、撑满宽度；布局用 CSS Grid 实现（而不是早期的 flex-wrap），控件行跟卡片顶/底内边距都固定 10px，中间（文字块到控件行）的间距自适应吃掉剩余空间，不会因为控件本身高度不同（步进器 40px vs 开关 20px）而挤压相邻内容
- **卡片圆角/内边距参照设计稿调整**（方案 A，所有尺寸统一）—— 圆角从 20px 改成 24px、内边距从 14px 改成 10px（`.plan-A` 的 `--radius`/`--pad` 变量，四档卡片共用）；同时空调步进器的"−/+"按钮从固定 22px 的小方块改成靠 flex 均分宽度的圆角胶囊（40px 高、20px 圆角），跟数值一起撑满整行，视觉上更接近参考设计稿
- **选中卡片后浮层不再遮挡列表底部**（2026-09-29）—— 选中任意一张卡片、屏幕底部浮起分享/收藏/更换房间工具栏时，设备列表底部内边距会临时从 40px 加到 79px（实测浮层渲染高度 47px + 32px），滚动到底部也不会被浮层压住最后一张卡片；取消选中后内边距立刻恢复 40px。用 `.phone:has(> .batch-bar.show) .grid{padding-bottom:79px}` 实现，靠 `:has()` 把互为兄弟节点的 `.batch-bar` 和 `.grid` 关联起来。浮层离屏幕底部的距离统一为 24px（原来是 14px）；移动端窄屏下浮层改成 `position:fixed` 直接锚定浏览器视口底部（而不是跟桌面一样相对 `.phone` 用 `position:absolute`），因为移动端 `.phone` 高度会随卡片内容撑高、不再是固定高度容器，用 absolute 会导致浮层看起来跟着列表内容一起滚动、不吸底

## 文件说明

- `index.html` —— 整个 demo，单文件，没有依赖，双击就能在浏览器打开

## 怎么改

所有设备数据集中在 `index.html` 底部的 `DEVICES` 数组里，改名称、房间、图标都在那一处；`sizes` 字段控制这台设备支持切换到哪些卡片尺寸。

两套方案的所有尺寸写在 CSS 的 `.plan-A` 和 `.plan-B` 里，是一组变量，改数值就能调方案，不用动结构。
