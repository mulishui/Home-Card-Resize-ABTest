# Home 页切换卡片 AB Test demo

IoT App 首页「设备卡片尺寸」两套方案的可交互原型，用来做 A/B 用户调研。

## 这是什么

页面模拟的是 **编辑态** 下的首页（不是日常使用状态）：用户进来就是在调整卡片布局，所以刻意去掉了房间切换、室内温湿度这些信息，避免干扰测试判断。

| | 方案 A | 方案 B |
|---|---|---|
| 排列 | 2 列大卡片 | 3 列小卡片 |
| 卡片高 | 116px | 94px |
| 卡片内边距 / 圆角 | 10px / 28px | 10px / 16px |
| 图标 | 40px | 26px |
| 尺寸按钮 | 24px | 22px |
| 设备名 / 房间名 | 16px / 14px | 12.5px / 10.5px |

顶部可以切换：单看方案 A、单看方案 B、两个方案并排对比（并排模式在手机上会自动隐藏，屏幕太窄）。

## 已经能用的交互

- **长按卡片拖动排序** —— 按住约 0.1 秒进入拖拽，松手落位，其他卡片带动画让位；拖拽浮层拖出手机边框时会被物理裁切掉（不是位置被钳制在框内），跟手体验不受影响
- **点卡片右上角 ⤢**（方案 A）—— 轮播式切换卡片尺寸：按 1×0.5 → 1×1 → 2×1 → 2×2 循环，跳过该设备不支持的档位；所有设备初始都是 1×1，支持哪些档位由 `DEVICES` 里每项的 `sizes` 决定（方案 B 暂未接入，点击仍是占位提示）
- **卡片排布规则**（方案 A）—— 改尺寸不会把已经排好的卡片”回填”挪位：改变某张卡片尺寸时，排在它前面的卡片位置完全不动，只有它自己和排在它后面的卡片会跟着顺势重排，且不会跳回前面已经跳过的空位。1×0.5 卡片比较特殊：单独一张时算法内部仍按占满一个完整 1×1 高度的槽位参与占位判断（不会被别的卡片占用，这片空白也能接住拖拽悬停判定），但如果这半格所在那一行确实没有任何卡片渲染进去，视觉上会把这一行收缩成 0 高度，不留空档；只有列表里紧跟着它、中间没被别的卡片打断的下一张也是 1×0.5，两者才会叠在一起共享同一个槽位。这套逻辑靠 JS 显式计算每张卡片的格子位置（`index.html` 里的 `computeLayout()` / `relayout()`），没有用浏览器原生的 CSS Grid 自动排布
- **拖拽与 1×0.5 配对的关系（不对称）** —— 只保护"落点"、不保护"起点"：拖到一对相邻 1×0.5 中间时，不会拆开插进去，而是被拖卡片和这一整对整体互换位置；但被拖卡片自己如果出发前是配对里的一张，拖走时**只带走它自己**，原地留下的搭档会自然变成孤立的 1×0.5（下方留空半格），不会被一起拖走。同一对里的两张 1×0.5 之间也能直接互相拖拽换上下顺序
- **换位判定的死区** —— 拖进目标卡片中心区域才会触发换位，四周留一圈死区防止边界抖动；孤立 1×0.5 卡片下方预留的空白也算在热区里，不用非得精确拖到那张小卡片本身
- **2×1 / 2×2 拖到任意一行上，整行都是换位热区** —— 棋盘固定两列、m/l 本身总是占满整行宽度，所以横坐标不参与判断：只按拖拽落点的纵坐标定位到目标"行带"（两张 1×1 并排、1×1 + 一对堆叠的 1×0.5、甚至一侧完全没有卡片渲染的真空白，都是同一种情况，统一处理），这一整行涉及到的卡片会被当成一个整体热区，拖到这一行的任意位置（包括卡片中间的缝隙、真空白区域）都能触发换位，触发后保持原有左右顺序整体换出去，行内不设死区；行与行之间同样不设死区——目标行带的命中范围会延伸到跟相邻行带的中点为止，不会贴着卡片自己的渲染矩形留出一条打不到的缝隙
- **2×1 / 2×2 卡片的状态内容**（方案 A）—— 支持切到这两档的设备会展示一个状态控件：开关型设备（电视/机器人/音箱/摄像头/门锁）显示 iOS 风格开关 + 状态文字（如"清扫中""已上锁"），可调数值型设备（净化器）显示进度条 + 数值文字（如"70% · AQI 优"），客厅空调显示"− 数值 +"步进器（如"− 25°❄ +"）。2×1 只多了横向空间，控件紧凑地排在设备名右侧、卡片高度不变；2×2 横纵向空间都翻倍，控件放大一档、推到卡片底部（客厅空调只支持到 2×1，没有 2×2 档）。目前只做静态视觉展示，不接入真实点击/拖动交互。1×0.5 / 1×1 档位、以及不支持 2×1/2×2 的其余设备完全不受影响
- **编辑态卡片多选 + 批量操作**（方案 A/B 通用）—— 直接点击卡片本身（不是长按、不是单独的多选入口）即可选中/取消：选中的卡片**背景保持原来的白色不变**，只靠右下角出现的勾选圆圈指示选中（1×0.5 尺寸空间紧张，勾选圆圈挪到 ⤢ 尺寸按钮左侧、垂直居中显示，避免和按钮打架，大小跟其他尺寸完全一样，只是位置不同）；顶部标题实时显示"N 设备选中"，一张都没选时恢复"编辑卡片"。选中数 ≥1 时，屏幕底部会浮起一条工具栏（分享 / 收藏 / 更换房间），点击目前只弹出占位 toast，不接入真实的分享/收藏状态/换房间逻辑。选中状态是每台手机（每个 `.grid`）各自独立的 DOM 状态，并排对比模式下两侧互不影响。点击判定复用了拖拽逻辑里已有的"长按计时器是否触发过"标志位，长按阈值经过几轮调整目前是 180ms（100ms → 350ms 解决点击误判成拖拽 → 200ms → 180ms，逐步压缩到用户觉得拖拽响应够快、同时点击依然不会误判的区间），保证普通点击稳定判定为选中、只有真正长按才会进入拖拽
- **2×1 卡片的两行布局**（方案 A，所有支持 2×1 的设备统一）—— 图标 + 设备名/房间 + ⤢ 尺寸按钮在同一行（横向多出来的空间刚好一次放下），状态控件（开关/进度条/步进器）独占下一行、居中撑满宽度，不再是"图标一行、名称+控件挤在同一行右侧"的旧样式
- **卡片圆角/内边距参照设计稿调整**（方案 A，所有尺寸统一）—— 圆角从 20px 改成 24px、内边距从 14px 改成 10px（`.plan-A` 的 `--radius`/`--pad` 变量，四档卡片共用）；同时空调步进器的"−/+"按钮从固定 22px 的小方块改成靠 flex 均分宽度的圆角胶囊（32px 高、16px 圆角），跟数值一起撑满整行，视觉上更接近参考设计稿
- 底部一份占位问卷，等正式题目替换

## 怎么改

所有设备数据集中在 `index.html` 底部的 `DEVICES` 数组里，改名称、房间、图标都在那一处；`sizes` 字段控制这台设备支持切换到哪些卡片尺寸。

两套方案的所有尺寸写在 CSS 的 `.plan-A` 和 `.plan-B` 里，是一组变量，改数值就能调方案，不用动结构。
